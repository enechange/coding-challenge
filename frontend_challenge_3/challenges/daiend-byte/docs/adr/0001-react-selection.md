# ADR-0001: フロントエンドフレームワークに React を採用する

## Status

Accepted

## Context

電気料金シミュレーションを起点に、今後継続的に開発・運用していくプロダクトラインのフロントエンド基盤を選定する。単一画面の実装可否ではなく、「チームで長期間、採用・育成しながら保守する」前提での技術選定であり、テックリードとして組織全体の観点から判断する。

要件面（段階的な出し分けフォーム、リアルタイムバリデーション、型安全、将来の API 差し替え）はどちらのフレームワークでも十分実現可能であり、選定の決め手にはならない。したがって、要件適合は前提条件（満たして当然）とし、組織ドライバーで判断する。

### 判断基準（組織ドライバー・重み順）

1. 採用優位性・人材確保のしやすさ（採用リスクの低減）
2. スケール時の開発生産性・大規模保守性
3. 育成・オンボーディング容易性（教材・事例・成長経路を含む）
4. エコシステムの持続性と技術的リスク（バス係数・移行前例）
5. 将来拡張性（メタフレームワーク・モバイルへの展開余地）
6. 【前提】プロダクト要件適合・型安全性（両者充足のため決め手にしない）

### 検討した選択肢

**React**

採用優位性・人材確保（企業視点）: 技術選定は開発者個人の好みではなく、「企業として採用市場から人材を確保しやすいか」で判断する。母集団が大きいほど採用のリードタイム・ミスマッチリスクが下がるため、開発者人口（供給側）の指標を根拠とする。

- React は Stack Overflow Developer Survey 2025 においてプロフェッショナル開発者の 46.9% が利用しており、Vue.js（18.4%）を大きく上回る、最も広く使われているフレームワークである [^1]
- State of JavaScript 2025 においても React は最多利用フレームワークの地位を維持している [^2]

React を扱えるエンジニアの母集団はグローバルで Vue の 2〜3 倍規模に達しており、採用市場における人材の厚みという点で明確に優位である。

生産性・育成・リスク:

- 初速はやや劣るが、型安全・コンポーネント合成・巨大エコシステムにより規模拡大時の保守性で優れる
- 学習曲線は急だが、教材・事例・コミュニティ回答の層が厚く、独学・OJT の両面で情報に困らない。React Native 等へのスキル転用性も高く、成長経路が広い
- Meta の後ろ盾と広範なエコシステムでバス係数が低い。メタフレームワーク（Next.js 等）やモバイル展開の選択肢を将来に残せる

**Vue（不採用）**

- 生産性（初速）と学習曲線の緩さは明確な強みで、初学者の早期戦力化に有利
- SFC・公式ルーター/ストア同梱により意思決定コストが小さい
- 一方、採用母集団・エコシステム幅は React に劣り、v2→v3 の移行前例が示すとおりメジャー移行時のコストという長期リスクを抱える
- 本件の組織ドライバー（採用・持続性・成長経路）で React を上回る決め手に欠ける

## Decision

React を採用する。Vue の「初速の生産性」と「オンボーディングの容易さ」という利点を認識した上で、採用優位性・スケール時保守性・エコシステム持続性・成長経路という長期の組織ドライバーで React が総合的に優ると判断した。

React の弱点（周辺技術の意思決定過多、記述量、書き方のばらつき、オンボーディングの急峻さ）は、フレームワーク選定とは別レイヤーの「チーム規約」で抑える:

- 構造化アーキテクチャの採用（feature ベースの標準構成、[ADR-0003](./0003-directory-structure.md)）で迷いとばらつきを削減
- Lint / フォーマッタ / import 境界の強制（[ADR-0007](./0007-toolchain.md)）で品質を機械化
- 共通コンポーネント・スキーマ駆動バリデーションの標準化（[ADR-0005](./0005-form-validation.md), [ADR-0009](./0009-ui-components.md)）で学習面を圧縮
- ADR による意思決定の記録で、新規参画者の立ち上がりを支援

## Consequences

- 正: 採用・育成・長期保守の観点で持続可能な基盤を確立できる
- 正: 将来のメタフレームワーク／モバイル展開の選択肢を確保できる
- 負: 初期のオンボーディングコストと規約整備の初期投資が必要 → 上記緩和策で対応
- 付随: ビルド・状態管理・フォーム・スタイリング等の周辺選定を別途 ADR 化する
